**Open research questions** (must be resolved before implementation):

1. **A6 — `scripts/rewrite_doc_refs.py` versioned→versioned mapping.** At the v0.0 → v0.1 cut, active forward-pointing references should be rewritten `docs/0.0/X.md → docs/0.1/X.md`, but historical citations (e.g., "see D5 in `docs/0.0/DESIGN-log.md`" — a real frozen-record pin) should stay pinned. PR-016's script handles flat→versioned cleanly but doesn't distinguish active from historical. Two candidate approaches:
   - **Opt-out list**: an explicit set of files / line ranges that should NOT be rewritten
   - **Smarter regex**: heuristic detection (e.g., references inside "## Decisions" sections or "see Dn in" patterns stay pinned)
   Success criteria: a concrete update to `scripts/rewrite_doc_refs.py` that handles the v0.0 → v0.1 cut correctly. Tested empirically on a dry-run of the actual repo state. Idempotency contract preserved (re-running `--dry-run` after apply reports 0 changes).

2. **CHANGELOG audit.** Walk every commit from `v0.0.1..HEAD` and surface user-facing changes for the `[0.1.0]` entry. Anchored on the `[Unreleased]` entries each PR-017/018/019/020 should have left behind — verify they're complete and consolidated.

3. **Post-merge tag command + verification.** Per `docs/VERSIONING.md §7`: tag `v0.1.0` at the PR-021 merge commit. Document the exact post-merge tag command for the user to run (mirroring PR-016's post-merge tag command for `v0.0.1`). Include verification: `git describe --tags` matches `v0.1.0`, `pyproject.toml` `version` matches, `src/rux_ml/__init__.py` `__version__` matches.

4. **`prs/PR-017-*.md` through `prs/PR-020-*.md` `Landed-in:` flip.** Each merged v0.1 PR should have its `Landed-in:` value flipped from `(not yet landed)` to `v0.1.0` in this PR's commit.
