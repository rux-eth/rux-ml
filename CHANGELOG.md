# Changelog

All notable user-facing changes to `rux-ml`. Format: [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/). Versioning policy: see [`docs/VERSIONING.md`](docs/VERSIONING.md).

## [Unreleased]

### Fixed
- `configs/base.toml [cv]` no longer carries variant-specific defaults. `shuffle = true` (a `KFoldCV`-only field) and `n_splits = 5` (absent from `CombinatorialPurgedCV`, which uses `n_folds`) leaked across the discriminator on `deep_merge` and tripped Pydantic's `extra="forbid"` whenever a problem TOML switched `kind` to `time_series` / `group_kfold` / `cpcv`. Both fields are now schema-defaults (preserving identical behavior for kfold users). New `tests/config/test_base_toml_discriminator_hygiene.py` walks every top-level discriminated union (`[cv]`, `[training]`, `[solving]`) and asserts no variant-specific field lives at the base-table position — future regressions of the same shape fail CI, not the user at runtime (PR-022).
- `docs/CONVENTIONS.md` HPO objective section + `docs/ARCHITECTURE.md` HPO components section now honestly characterize the test-fold-as-eval_set design as a research-acknowledged pragmatic deviation from textbook CV (Position A of four practitioner positions), not as a clean pattern inherited from Optuna's WilcoxonPruner recipe. The HPO bias compounding risk is now documented, and the two alternatives (Position B — inner val from train fold, sklearn's `HistGradientBoosting*` default; Position C — no early stopping in CV with post-CV retrain, XGBoost's own recommendation) are noted as explicitly available, deferred to a future Tier-2 study (PR-022 Phase 3 research, 2026-05-18).
- **Stacked-panel CV no longer silently under-embargoes per-asset forward labels.** `TimeSeriesSplitCV.gap` is row-count; on a K-row-per-timestamp panel that collapsed to ≈ `gap / K` timestamps of per-asset separation (1084-asset hourly panel: `gap=24` ≈ 0.022 timestamps, not 24 hours). PR-023 surfaces two panel-aware paths — `TimeSeriesSplitCV.embargo_time="<duration>"` (D2; e.g. `"24h"`) and the new `PanelCombinatorialPurgedCV` variant (D1) that folds over unique sorted timestamps so per-asset purge is timestamp-atomic. Pre-existing single-asset users are unaffected; defaults preserve v0.1.1 row-count behavior. Live finding from the 2026-05-18 first-real-dataset run; research-backed by sktime / Nixtla / Darts (polymorphic time-units convention) + mlfinlab `StackedCombinatorialPurgedKFold` + Numerai era-CV (panel-CPCV convention).

### Added
- `docs/CONVENTIONS.md` Configuration Conventions: new subsection on **base.toml discriminator-table hygiene** — variant-specific knobs go in `configs/problems/<n>.toml`, not base. Enforced by the new structural test. Documents `kind` vs `type` discriminator field distinction (PR-022).
- `docs/CONVENTIONS.md` CV strategy conventions: new subsection on **`TimeSeriesSplitCV.gap` row-vs-time semantics** — `gap` is row-count not time-units; on stacked panels this collapses to <1 hour of per-asset embargo when many assets share each timestamp. Forward-references PR-023 (time-aware embargo for panel data). Live finding from the 2026-05-18 first-real-dataset run (PR-022).
- **`PanelCombinatorialPurgedCV` Splitter variant** (PR-023 D1). New `[cv] kind = "panel_cpcv"` variant: folds are computed over the **unique sorted timestamps** read from `time_column`; skfolio CPCV runs on the timestamp axis (so `target_horizon_bars` and `embargo_pct` are interpreted in timestamp units); each timestamp-level fold maps back to row indices, making per-asset purge timestamp-atomic. `asset_column` is required and validated at split time. Convention: mlfinlab `StackedCombinatorialPurgedKFold` + Numerai era-CV.
- **Ergonomic AFML knobs on `CombinatorialPurgedCV`** (PR-023 D3). New fields `target_horizon_bars: int = 0` + `embargo_pct: float = 0.0`; the splitter converts internally to skfolio's row-count `purged_size` / `embargo_size = int(N * embargo_pct)` per AFML Snippet 7.3. When both ergonomic and row-count siblings are non-zero, the row-count value wins (strict opt-in). Defaults preserve v0.1.1 behavior.
- **`docs/ARCHITECTURE.md` Decision Rules**: new entry for **CV strategy by data shape** (single-asset vs stacked panel; row-count vs time-unit embargo) per PR-023 D1/D2 (refines the existing per-strategy default table to flag the panel foot-gun explicitly).
- **`docs/CONVENTIONS.md` CV strategy conventions**: panel row added to the CV-default-by-data-shape table; new `TimeSeriesSplitCV.embargo_time` polymorphic semantics subsection; new `PanelCombinatorialPurgedCV` subsection; mandatory **skfolio purge precision gap** note (PR-023 D4) documenting that skfolio's scalar two-sided `purged_size` is conservative-correct (drops more than AFML's interval-overlap; never leaks) and pointing users to mlfinlab/timeseriescv for interval-overlap precision.
- `tests/data/test_panel_cv.py` — 20 new tests across three layers: hand-verified index fixtures on tiny synthetic panels (3 assets × 9 timestamps); property tests (pairwise-disjoint train/test, per-asset embargo loop, timestamp atomicity, n_splits combinatorial); shuffle-null tripwire (no-skill baseline residual ≈ y_var) for stacked-panel CV (PR-023 D5).

### Changed
- **`TimeSeriesSplitCV` polymorphic embargo** (PR-023 D2). New fields `time_column: str | None = None` + `embargo_time: int | str | None = None`. When `embargo_time` is set it wins over `gap`: an `int` is row-count (matches `gap` semantics); a duration string like `"24h"` requires `time_column` and is parsed via `pandas.Timedelta`, then translated to a row-count gap by computing the median delta between unique sorted timestamps and the mean rows-per-unique-timestamp. Exact on regular bars; conservative best-guess on irregular bars (out-of-scope precision work tracked in `docs/0.2/RESEARCH-BACKLOG.md` A2). Defaults preserve v0.1.1 behavior. Convention: sktime `SlidingWindowSplitter`, Nixtla `mlforecast.cross_validation`, Darts `historical_forecasts`.

## [0.1.0] - 2026-05-18

### Added
- LightGBM Trainer family. Install via `uv sync --extra lightgbm`. Selected per problem via `[training]` `kind = "lightgbm"`. CPU-only in v0.1 (per Q-GPU research: LightGBM-GPU is 8-28x slower than XGBoost-GPU on workbench-scale data; install path via uv is non-trivial). Categorical features integrate cleanly with the existing `_ColumnRouter` (no pipeline changes); reference HPO search-space template at `configs/search_spaces/lightgbm.toml` (PR-018).
- CatBoost Trainer family. Install via `uv sync --extra catboost`. Selected per problem via `[training]` `kind = "catboost"`. **GPU is the default** — CatBoost ships prebuilt CUDA wheels via `uv add catboost`, no extras / source build / container delta needed (RTX 4090 field-confirmed). `cat_features=` is auto-extracted from the DataFrame at fit time by `_CatBoostTrainerShim` (CatBoost does NOT auto-detect pandas Categorical dtype unlike LightGBM). Uses Intel TBB threading, NOT OpenMP — factory reads `OMP_NUM_THREADS` and passes explicitly as `thread_count=`. Reference HPO search-space template at `configs/search_spaces/catboost.toml` with 7 search dims (PR-019).
- **Solver layer**. Parallel top-level surface to the Trainer layer per `docs/0.1/DESIGN-log.md` Q1 (two parallel `typing.Protocol`s, no shared parent). New `src/rux_ml/solving/` subpackage + `SOLVER_FAMILIES` registry + `make_solver(cfg)` factory + `Solver.solve(problem) → SolverResult`. First family: **CVXPY** (zero dep addition — cvxpy + clarabel were already transitive via skfolio; promoted to direct deps). `cfg.solving.solver` selects a backend (`CLARABEL` default; `OSQP` / `SCS` / `ECOS` / `HIGHS` also routable through cvxpy). `cfg.solving.solver_opts: dict[str, Any]` is the escape hatch for backend-specific tolerances/iter knobs. New CLI verb: `rux-ml solve --problem <name>` runs a single solve (analog of `rux-ml train`; solver-internal HPO deferred to follow-up). Per Q-Shape research = partial-mirror integration: solver runs reuse Optuna study + per-trial provenance (`TrialAttrs` extended with Optional `solving_cfg_hash` + `solver_status` + `objective_value` + `solver_iter_count` + `solve_time_s`) but bypass `cfg.data` / `cfg.cv` / fittable-model registry (PR-020).

### Changed
- Adopt vibe-rails hybrid docs-versioning layout: temporal docs (`DESIGN-log`, `RESEARCH-BACKLOG`, `ROADMAP`) move under `docs/0.0/`; flat SSOT files (`ARCHITECTURE`, `CONSTRAINTS`, `CONVENTIONS`) stay at `docs/`. Add `docs/VERSIONING.md`, `docs/DEPLOYMENT.md`, `/CHANGELOG.md`. Add `Landed-in:` header to every numbered PR file. Add `scripts/rewrite_doc_refs.py` migrator + `make rewrite-doc-refs` targets. Append Per-Phase Approval Gate (NON-NEGOTIABLE) to `docs/CONSTRAINTS.md` — Claude halts at every phase boundary of every multi-phase procedure (PR-016).
- Trainer registry refactor: `src/rux_ml/training/` is now multi-family. XGBoost integration moved into `src/rux_ml/training/xgboost/` subpackage. `TrainingConfig` is a Pydantic v2 discriminated union over per-family variants with `kind` discriminator. `TRAINER_FAMILIES` registry dict (B-explicit, HF transformers `MODEL_MAPPING_NAMES` pattern). New parametrized conformance test `tests/training/test_registry_conformance.py` is the stale-path tripwire (PR-017).
- Sentinel `PASSTHROUGH_TO_XGB_CATEGORICAL` renamed to `PASSTHROUGH_NATIVE_CATEGORICAL` — same sentinel now serves XGBoost AND LightGBM AND future CatBoost (PR-018 Q-Cat).
- v0.0 → v0.1 docs-version cut: `scripts/rewrite_doc_refs.py` PATH_REWRITES updated for `docs/0.0/* → docs/0.1/*` migration; added per-file `OPT_OUT_GLOBS` (skips `prs/`, `docs/0.0/`, `docs/0.1/`, `src/`, `tests/`) and per-line `<!-- rewrite-doc-refs:skip-line -->` sentinel for locking historical citations (e.g., "D1–D17 in DESIGN-log.md") against re-runs. Idempotency contract preserved (PR-021).

## [0.0.1] - 2026-05-16

### Added
- Initial v0 workbench: end-to-end **data → features → training → tuning → run logging → registry promotion** lifecycle. Single CLI (`rux-ml`) over the Python package (`rux_ml`). XGBoost-first via GPU (`device="cuda"`); three-tier TOML config (`base.toml` → `problems/<n>.toml` → `studies/<n>.toml`) with `CLI > env > .env > study > problem > base` override precedence. Optuna sequential trials with subprocess-per-trial spawn isolation, SQLite study, K-fold CV-mean objective, WilcoxonPruner, TPE sampler. Five `Splitter` strategies (`KFold` / `StratifiedKFold` / `TimeSeriesSplit` / `GroupKFold` / `CombinatorialPurgedCV`). Two-file model bundle (`pipeline.skops` + `model.ubj` + Pydantic-validated `manifest.json`); atomic `champion.json` rewrite. Per-trial provenance triple in `user_attrs` (`data_hash`, per-layer/root config hashes, `git_sha`, `entropy_hex`, `image_digest`, library/CUDA/driver versions, `omp_threads`, `peak_rss_mb`). Memory watchdog with `MemoryPressureError` → `optuna.TrialPruned`. Tolerance-based golden regression tests (CPU bit-exact contract). Container image with NVIDIA CUDA 12.4.1 base, GPU passthrough via Compose, `mem_limit: 32g`, image-digest pinning (PR-001 through PR-015).
